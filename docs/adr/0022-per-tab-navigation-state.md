# ADR 0022: 口座/送金タブを常設し、それぞれ独立したナビゲーション状態にする

## ステータス

Accepted。`web-ui`の`CustomerFlow.tsx`・`CustomerAccountDetail.tsx`・`TransferDetailScreen.tsx`・
`AppBar.tsx`に実装する。[[0021-account-transfer-cross-links]]が導入した`returnTo`(直前の画面を
1段だけ覚える仕組み)を、本ADRで廃止して置き換える。

## コンテキスト

[[0021]]で口座詳細⇔送金詳細の相互リンクを実装し実際に使ってみたところ、ユーザーから
「送金メニューから辿って口座詳細にたどり着いた際、戻るボタンを押すと送金詳細へ戻る挙動に
戸惑った」という報告を受けた。

議論の結果、これは実装のバグではなく設計そのものの問題だと分かった。[[0021]]の`returnTo`は
「戻る」というボタンに、通常の意味(そのタブの一覧へ戻る)と、相互リンクを辿った場合の
特別な意味(リンク元の画面へ戻る)という**2つの異なる意味を経路によって切り替えて**持たせて
いた。相互リンクが存在しなかった従来はこの経路が1種類しかなかったため問題が表面化しなかった
だけで、複数の経路が生まれた時点で「戻る」の意味が予測できないという設計上の欠陥が露呈した。

あるべき姿から考え直すと、一般的なタブ型アプリのナビゲーションでは:
- タブ(口座/送金)は常時表示され、いつでも切り替えられる。
- 各タブはそれぞれ独立した画面状態を持ち、タブを離れても保持される。
- 「戻る」は今いるタブの中だけを1段戻す、常に一定の意味を持つ操作。セクションをまたぐ移動は
  「戻る」の役目ではなく、タブ切り替えの役目。

という分離が標準的である。[[0021]]の`returnTo`はこの分離を守らず、「戻る」にタブをまたぐ
移動の責務まで持たせてしまっていたことが根本原因だった。

## 決定

### 1. `CustomerFlow.tsx`の状態を、単一の`View`共用体から**タブごとに独立した状態**へ組み替える

```
activeTab: "accounts" | "transfers"
accountsTabView: { screen: "list" } | { screen: "detail"; accountId }
transfersTabView: { screen: "list" } | { screen: "detail"; transferId }
```

`returnTo`フィールドは廃止する。タブ切り替え(`onSelectTab`)は`activeTab`を変更するだけで、
もう一方のタブの状態には一切触れない——[[0021]]の相互リンク(例: 送金詳細→この口座の
入出金履歴)は「`accountsTabView`をその口座の詳細にして`activeTab`を`accounts`に切り替える」
だけになり、`transfersTabView`(元いた送金詳細)はそのまま保持される。送金タブに戻れば、
`returnTo`という特別な記憶の仕組み無しに、リンクを踏む前の場所へ自然に戻る。

組戻し(`onRecalled`、新しいtransferIdへの遷移)も同様に単純化される——`returnTo`を
引き継ぐ処理が不要になり、今のタブの状態を新しいtransferIdで上書きするだけで済む。

### 2. `CustomerTabBar`を詳細画面にも常設する

`CustomerAccountDetail.tsx`・`TransferDetailScreen.tsx`は、それぞれの`DetailAppBar`の直後に
`CustomerTabBar`を追加する(表示位置・見た目は一覧画面と同じ上部セグメント型のまま——
[[0009-web-ui-customer-experience-and-channel-emulation]]が踏襲してきた画面デザインとの
一貫性を優先し、下部固定ナビ化のような見た目の作り替えは今回のあるべき姿の本質ではないと
判断した)。これにより、詳細画面からでも常にセクションを直接切り替えられる。

### 3. `DetailAppBar`の`backLabel`を呼び出し元ごとに必須にする

決定1の結果、「戻る」は画面ごとに常に一定の戻り先を持つようになったため、
`aria-label`も画面ごとに固定できる。従来は`DetailAppBar`内部で「口座一覧へ戻る」に
固定されており、`TransferDetailScreen`(実際には送金一覧へ戻る)でも同じ文言になっていた
潜在的なバグを合わせて修正する——`CustomerAccountDetail`は"口座一覧へ戻る"、
`TransferDetailScreen`は"送金一覧へ戻る"を明示的に渡す。

## トレードオフ

- **タブ切り替えは「今いる状態を保ったまま」であり、「一覧へ戻る」ではない**: あるタブの
  詳細画面を見ている状態で、いったん別タブへ切り替えてから同じタブに戻ると、一覧ではなく
  直前の詳細画面が再び表示される。これは意図的な仕様(iOSのタブナビゲーション等、多くの
  アプリの標準的な挙動)だが、「タブ=そのセクションの入り口」という素朴な期待とは異なる
  ため、初見では気づきにくい可能性がある。「一覧に戻りたい」場合は「戻る」を使う、という
  使い分けが必要。
- **各タブの状態は最大2階層(一覧/詳細)のみ**: 汎用のナビゲーションスタック(任意の深さの
  履歴)は導入していない——このアプリは現状どのタブも一覧→詳細の2階層しか無いため、
  タブごとに単純な共用体2値を持てば足りる。将来3階層目が必要になった場合は改めて設計する。

## 却下した代替案

- **`returnTo`を維持しつつ、タブバーだけを詳細画面に追加する**: 「戻る」の経路依存という
  混乱の根本原因を放置したまま、回避策(タブでジャンプすればよい)を追加するだけになる。
  「あるべき姿」を基準に考え直した結果、根本(状態をタブごとに分離すべきだったこと)を
  正すほうを選んだ。
- **タブバーを画面下部固定のナビゲーションに作り替える**: 実際の銀行アプリでよく見る形に
  近づく一方、レイアウトの作り替えを伴い影響範囲が大きい。今回の問題(セクション間移動の
  手段が詳細画面に無いこと)を解決するのに必要な変更ではないため見送った。
